# Aho-Corasick Multi-Pattern Search Benchmark

A Python benchmark project that compares the classic Aho-Corasick multi-pattern string-matching algorithm against a brute-force baseline on generated DNA-like text.

The repository is designed to show how Aho-Corasick scales when searching for many patterns in one text, and to compare correctness, timing, and comparison counts between the two implementations.

## Overview

When matching many patterns against one text, a naive approach checks every pattern at every possible starting position. This is simple, but it becomes extremely expensive as the number of patterns or text size grows.

Aho-Corasick avoids that repeated work by:

- building a trie from all patterns,
- creating failure links between trie states,
- scanning the input text in a single forward pass,
- reporting all matches as the automaton reaches output states.

This project benchmarks both methods on deterministic DNA-style data and records their behavior in a repeatable way.

## What is in the project?

- `aho_corasick.py` — implementation of the Aho-Corasick automaton and search wrapper
- `brute_force.py` — naive baseline implementation for comparison
- `benchmark.py` — benchmark runner, dataset generation, result saving, and optional chart generation
- `results.csv` — sample output from a benchmark run
- `benchmark_report.png` — sample chart generated from benchmark data
- `README.md` — project documentation

## Benchmark methodology

For each configuration, `benchmark.py` does the following:

1. Generates a random text using the DNA alphabet `A`, `T`, `C`, and `G`
2. Generates a set of random patterns
3. Embeds a small number of patterns into the text
4. Runs both algorithms three times per configuration
5. Measures elapsed wall-clock time
6. Counts comparison operations used as a benchmark metric
7. Verifies that both algorithms return the same set of matches
8. Saves the results to `results.csv`
9. Produces `benchmark_report.png` if Matplotlib is installed

The benchmark configurations in `benchmark.py` currently include:

- text lengths from 10,000 to 5,000,000 characters
- pattern counts from 5 to 100
- pattern lengths from 8 to 12 characters

## Installation

There is no formal dependency manifest in this project, so setup is lightweight.

### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### Windows PowerShell

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
```

If PowerShell blocks activation, use the environment’s Python directly:

```powershell
.\.venv\Scripts\python.exe benchmark.py
```

To generate the PNG chart, install Matplotlib:

```bash
python -m pip install matplotlib
```

## Running the benchmark

From the repository root, run:

```bash
python benchmark.py
```

This prints live timing information while each benchmark run executes, then writes:

- `results.csv`
- `benchmark_report.png` (if Matplotlib is available)

## Python API

Both implementations expose a simple function-based interface.

```python
from aho_corasick import aho_corasick_search
from brute_force import brute_force_search

text = "ushers"
patterns = ["he", "she", "hers"]

ac_matches, ac_count = aho_corasick_search(text, patterns)
bf_matches, bf_count = brute_force_search(text, patterns)

print(sorted(ac_matches))
print(sorted(bf_matches))
```

Each function returns:

- a list of matches in the form `(pattern, start_index)`, and
- a comparison count used for benchmarking.

For correctness checks, compare match sets rather than relying on list ordering.

## Aho-Corasick implementation summary

The implementation in `aho_corasick.py` contains:

- trie construction for all patterns,
- breadth-first failure-link computation,
- output propagation through failure states,
- linear-time scanning of the input text.

This allows the system to detect matches for many patterns without restarting the search from the beginning for each pattern.

## Brute-force baseline summary

The implementation in `brute_force.py` works as a naive baseline:

- iterate over each pattern,
- slide the pattern across all possible starting positions,
- compare characters until there is a mismatch,
- record a match when the full pattern matches.

This is simple and correct, but much slower than Aho-Corasick as patterns become numerous or text becomes large.

## Sample benchmark results

The sample output stored in `results.csv` shows the expected pattern: as the input size and pattern count grow, Aho-Corasick becomes dramatically faster than the brute-force baseline.

| Config | Text Length | Patterns | Brute Force Avg (ms) | Aho-Corasick Avg (ms) | Speedup |
| --- | ---: | ---: | ---: | ---: | ---: |
| Config 1 | 10,000 | 5 | 107.15 | 102.24 | 1.05× |
| Config 2 | 100,000 | 5 | 109.45 | 114.06 | 0.96× |
| Config 3 | 100,000 | 20 | 284.75 | 108.72 | 2.62× |
| Config 4 | 1,000,000 | 20 | 2499.89 | 236.22 | 10.58× |
| Config 5 | 1,000,000 | 50 | 7330.15 | 237.59 | 30.85× |
| Config 6 | 5,000,000 | 100 | 76797.58 | 951.36 | 80.72× |

These results illustrate the classic scaling advantage of Aho-Corasick, especially when searching for many patterns at once.

## Notes on the comparison metric

The comparison counters are useful for benchmarking, but they are not perfectly equivalent low-level operation counts across both implementations.

- `bf_comparisons` counts character-equality checks in the brute-force search.
- `ac_comparisons` counts one lookup per scanned character in the automaton.
- Wall-clock timing is machine- and runtime-dependent, so comparisons should be interpreted comparatively.

## Troubleshooting

### PNG chart is not created

Install Matplotlib in the same environment that runs the benchmark:

```bash
python -m pip install matplotlib
```

### Virtual environment activation issue on Windows

If activation fails, call the environment directly:

```powershell
.\.venv\Scripts\python.exe benchmark.py
```

### Benchmark is slow

The largest configuration processes a 5,000,000-character text with 100 patterns. This is expected to take longer in the brute-force version.
